# qwork 评审与改进汇总（2026-11-14）

> 对象：qwork v4.5.0（源码仓 `qwork-skill`）。结论基于三轮冷启动探针、两轮结构评审、一次与 OpenSpec 的约束机制对照。

## 一、总评

| 维度 | 评分 | 说明 |
|---|---|---|
| 方法/内容 | 8.5 | 四要素单一权威、验收驱动、领域手册扎实 |
| 工件结构 | 8 | 四要素互斥；黄金样例补齐 |
| 可交接性 | 8 | 派发八问 + 执行回执 + 冷启动演练 + who/when 字段 |
| 约束力 | 8 | close 门 + 归档事务；语义质量仍靠人 |
| 工程化 | 8 | 安装 `--check`、校验器、归档/总览；缺回归自动化 |
| 领域适配 | 8.5 | 驱动 A/B、熔断、接手、长测沉淀真实 |

## 二、已解决

- SKILL 12.4k → 7.3k 字符：领域手册拆入 `references/`。
- 与知识库侧规则解耦：只保留产出物交接边界。
- 执行授权修正：执行者读四要素 + data，只写 tasks/data。
- 收口可执行：tasks 勾选载体、阻塞收口、`git mv`/ignore、半残骨架补齐。
- 四要素定位收敛：做成什么样 / 怎么做 / 怎么组织 / 怎么验收。
- who/when 进工件：决策权、启动/停止条件、验收人。
- 追踪与门禁：S/C 稳定 ID + `tools/qwork-check.py`（dispatch/close）。
- 归档事务：`tools/qwork-archive.py`（过门、`git mv`、ignore 镜像、回滚、`--commit`）。
- 进度总览：`tools/qwork-status.py`（change/archive、四要素、C 覆盖、下一步、`--json`）。

## 三、仍缺

1. **回归**：探针与工具仍是手跑清单，未自动化。
2. **样本覆盖**：实验类偏驱动 A/B，纯软件性能路径缺判据模板。
3. **语义**：校验器只查形式与追踪，不判内容质量。
4. **分发**：可选 `qwork dispatch`（生成执行者提示包）未做。

## 四、路线

- **P1（已完成）**：稳定 ID（S/C）+ `tools/qwork-check.py`。
- **P2（已完成）**：`qwork-archive` 事务、`qwork-status --json`；可选 `qwork dispatch` 未做。
- **P3（持续）**：每条校验规则对应一次真实事故；月度回看假阳性；补纯软件性能判据。

## 五、North star

**冷启动重放**：新会话/子代理只拿 change 目录，首个动作正确、提问数趋近 0、能独立做完。

指标：冷启动提问数、收口返工率、归档出错数、交接耗时。
