# qwork 评审与改进汇总（2026-11-14）

> 对象：qwork v4.3.0（源码仓 `qwork-skill`）。结论基于三轮冷启动探针、两轮结构评审、一次与 OpenSpec 的约束机制对照。

## 一、总评

| 维度 | 评分 | 说明 |
|---|---|---|
| 方法/内容 | 8.5 | 四要素单一权威、验收驱动、领域手册扎实 |
| 工件结构 | 8 | 四要素互斥；黄金样例补齐 |
| 可交接性 | 8 | 派发八问 + 执行回执 + 冷启动演练 + who/when 字段 |
| 约束力 | 5 | 仍为散文规则，缺 `validate` 式退出码 |
| 工程化 | 6 | 安装 `--check`、本机扩展、发布闸门；缺回归自动化 |
| 领域适配 | 8.5 | 驱动 A/B、熔断、接手、长测沉淀真实 |

## 二、已解决

- SKILL 12.4k → 7.3k 字符：领域手册拆入 `references/`。
- 与知识库侧规则解耦：只保留产出物交接边界。
- 执行授权修正：执行者读四要素 + data，只写 tasks/data。
- 收口可执行：tasks 勾选载体、阻塞收口、`git mv`/ignore、半残骨架补齐。
- 四要素定位收敛：做成什么样 / 怎么做 / 怎么组织 / 怎么验收。
- who/when 进工件：决策权、启动/停止条件、验收人。

## 三、仍缺

1. **约束力**：没有 `qwork check` 门；规则靠 agent 自觉。
2. **追踪**：spec 维度 ↔ check 项 ↔ tasks 结果没有稳定 ID，收口仍靠人查。
3. **迁移**：归档仍是手工命令，只是规则写对了。
4. **回归**：探针是手跑清单，未自动化。
5. **样本覆盖**：实验类偏驱动 A/B，纯软件性能路径缺判据模板。

## 四、路线

- **P1（1–2 天）**：稳定 ID（S/C）+ `tools/qwork-check.py`（`--dispatch` / `--close` / `--strict` / `--json`）。
- **P2（2–3 天）**：`qwork archive` 事务、`qwork status --json`、可选 `qwork dispatch`。
- **P3（持续）**：每条校验规则对应一次真实事故；月度回看假阳性；补纯软件性能判据。

## 五、North star

**冷启动重放**：新会话/子代理只拿 change 目录，首个动作正确、提问数趋近 0、能独立做完。

指标：冷启动提问数、收口返工率、归档出错数、交接耗时。
